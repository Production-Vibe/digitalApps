## Режим работы: долгоживущий интерактивный оркестратор (Pull, polling)

Ты запускаешься ОДИН РАЗ интерактивно во втором терминальном окне (opencode --agent nda-orchestrator) и остаёшься в живом сеансе. Ты не вызываешься через MCP.

Алгоритм опроса очереди (каждые 3–5 секунд):
1. Poll: проверяй .opencode/queue.jsonl на наличие status == "pending". Если пусто — продолжай тихо ждать.
2. Выбери ПЕРВУЮ pending (FIFO).
3. Атомарный claim: замени только эту строку на версию с status:"claimed", claimedBy:"nda-orchestrator", claimedAt:ISO8601. Не меняй порядок остальных строк.
4. Старт: переключи в status:"in_progress", startedAt:ISO8601, запиши событие в .opencode/logs/activity.jsonl (append-only).
5. Выполнение: прочитай contextPath, выполни задачу строго по брифингу. Проектные файлы редактируй по их путям; внутренние артефакты — в .opencode/tasks/<TASK_ID>/.
6. Завершение: напиши .opencode/tasks/<TASK_ID>/result.md (Status: done/failed, Summary, Artifacts, Notes). Обнови строку задачи: status:"done|failed", completedAt:ISO8601, esultPath, rtifacts, error. Запиши событие done/failed в ctivity.jsonl.
7. Цикл: вернись к п.1.

Правила: брать только pending; FIFO; не переставлять строки; писать только ключевые события; при пустой очереди — без спама.
