# Глоссарий «ЦифровойНаряд»

Система цифрового управления производством подъёмных агрегатов (ПА) вместо
бумажных нарядов. Домен — русский: термины ниже на русском, идентификаторы в коде
английские.

Это **глоссарий, а не статус-борд**. Что происходит и что дальше — в
`docs/reports/STATUS.md`. Что сделано технически — в `docs/specs/`. Решения с
альтернативами — в `docs/specs/adr/`.

## Документы и поток

**Наряд** (`WorkOrders`):
Цифровой наряд оператора на изготовление партии деталей: код позиции номенклатуры,
обозначение, станок, количество, оператор. Канон наряда — здесь, не в бумаге и не в
Excel. Один запуск может дать несколько нарядов.
_Не путать с:_ «заказом», «заданием», «launch».
_Избегать:_ paper workorder, заявка.

**Запуск** (`Launches`):
Плановое задание мастера на конкретный ПА: позиция номенклатуры, количество, № ПА,
тип. Из него нач. смены выдаёт наряды.
_Не путать с:_ нарядом (наряд — производный от запуска).
_Избегать:_ партия, заказ, batch.

**Технологический переход** (`Transitions`):
Шаг техпроцесса внутри наряда: номер (`005`, `010`, `015…`), описание, время, плавка,
количество, станок. Оператор вносит по ходу работы, ОТК проверяет.
_Не путать с:_ изменением статуса наряда.
_Избегать:_ операция, этап, transition record.

**Итог закрытия** (`ClosedOrders`):
Принято/брак по наряду на момент закрытия ОТК, с причиной брака. Запись-дубликат
факта закрытия.
_Избегать:_ отчёт, закрытие наряда (это событие, а не запись).

**Смена** (`Shifts`):
Рабочая смена оператора на конкретном станке. Оператор открывает/закрывает; сервер
не даёт открыть на занятый станок и ограничивает 2 открытые смены.
_Не путать с:_ «смена статуса».
_Избегать:_ session.

**Печатный комплект** (`PrintQueue`):
Задание на печать приложений к наряду. Создаётся при выдаче наряда, забирается VBA.

## Номенклатура и КД

**Номенклатура** (`Catalog`):
Полный перечень позиций изделий. Код позиции — иерархический, разделители `.` и `/`
считаются взаимозаменяемыми по сегментам (`21.1/9` ≡ `21.1.9`). Лист — позиция с
полным набором полей; контейнер — её код без последнего сегмента.
_Избегать:_ каталог продукции, справочник изделий, номенклатурный справочник.

**Обозначение**:
Документный номер детали по ЕСКД (напр. `МТ 03.01.010.00.000 СБ`). Везде, где деталь
идентифицируется для человека, показывается пара «Обозначение — Наименование», а не
код позиции: код узла (`1.1/1/10`) не является обозначением детали.
_Не путать с:_ кодом позиции.
_Избегать:_ чертёжный номер, артикул.

**КД** (`ProductDoc`, `ProductDocLink`):
Конструкторская документация изделия — чертежи, маршрутные карты, карты нормирования,
эскизы. Одна деталь бывает в нескольких сборках, поэтому связь many-to-many.
Пути `P:\Элемент\…` и `\\FS1\Production\…` — сетевые, хранятся как метаданные,
наличие файлов не проверяется.
_Избегать:_ документация, чертёж (это один **тип** КД, не всё).

**Словарное поле** (`DictionaryValue`):
Поле каталога со справочником значений: тип заготовки, материал, марка, размер,
приоритет. В UI — строгий выбор (400 на мусор), в импорте — лояльный (`#N/A` → пусто,
синонимы → канон).

## Роли

**Мастер** (`master`):
Начальник цеха. Дерево номенклатуры, запуски на ПА, сводки, аналитика, печать,
CRUD номенклатуры и документов.

**Нач. смены** (`shift`):
Выдаёт наряды операторам из запусков: оператор, станок, количество.

**Оператор** (`operator`):
Открывает смену на станке, принимает наряды, вносит техпереходы. Может зарегистрироваться
сам на `/login`.

**ОТК** (`otk`):
Приёмка/брак/закрытие нарядов, возврат на доработку.

**Админ** (`admin`):
Superuser: проходит любой ролевой фильтр, создаёт/меняет роли/деактивирует
сотрудников. Не создаётся через UI — только сидом.

## Статусы

Статусы наряда (`NARYAD_STATUS`): `created` → `in_progress` → `waiting_otk` →
`closed`, плюс `rework` (доработка: ОТК вернул → оператор правит → снова
`waiting_otk`).

Статусы запуска (`LAUNCH_STATUS`): `to_launch` → `issued` → `in_work` → `done`.
Запуск меняется только из `to_launch`.

Источник правды по статусам — `server/src/lib/naryad-status.ts`. Не дублировать
словари в коде UI.

**Доработка** (`rework`):
Возврат наряда ОТК оператору на исправление. Прямое закрытие наряда из `rework` без
проверенных переходов допустимо.

## Контуры и стенды

**Два контура БД, не взаимозаменяемые:**

- **Стенд** (`docker compose`, host-порт `5434`, БД `digital_narad`) — на нём живёт
  демо-контур и гоняется E2E.
- **Дев-контур** (`npm run dev`, `server/.env`, БД `MOSD` на `localhost:5432`) —
  локальная разработка.

Данные контуров различаются; E2E идёт против стенда.

**Живое состояние** (`docs/reports/STATUS.md`):
Единственный источник правды «что сделано, что дальше, где деплой». Обновляется по
Definition of Done.

**Этап работы**:
Схема «План → Реализация → Проверка → Отчёт»; отчёт — в `docs/reports/`, по
завершении — запись в `STATUS.md`.

**Умное округление** (`roundSmart`):
Единое правило чисел: `|x| ≥ 0.01` → максимум 2 знака, `0 < |x| < 0.01` → до первой
значащей цифры, `0 → 0`, хвостовые нули в отображении убираются. Применяется на
записи в БД, в агрегатах и в UI.
