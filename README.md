# ЦифровойНаряд

Система управления производством подъёмных агрегатов (ПА). Заменяет бумажные наряды полноценным веб-интерфейсом для каждого участника процесса.

**Стек:** Excel (VBA) → Google Таблицы (хранилище данных) → Google Apps Script WebApp (веб-интерфейс и серверная логика).

**Суть:** номенклатура загружается из Excel (VBA-макрос), начальник цеха планирует запуски, распределяет на подъёмные агрегаты; начальник смены оперативно раскидывает работы операторам; операторы выполняют и фиксируют каждый технологический переход с параметрами; ОТК контролирует качество и закрывает наряды. Всё крутится непрерывно до полной готовности партии.

---

## Роли

### Начальник цеха

- Полная картина производства: дерево всей номенклатуры (изделия → сборки → детали/ПКИ), фильтры по узлам, типам обработки, поиск.
- Аналитика: загрузка ПА, KPI, процент готовности, что в работе, что стоит.
- Планирование запусков: selects позиции → назначает на конкретные ПА (номера 001–120) → система записывает запуск с количеством и привязкой к ПА. Автоматический расчёт количества (из иерархии) или ручной ввод. Проверка занятости ПА, визуальная сетка с цветовой индикацией.
- Управление очередью печати.

### Начальник смены

- Видит всё, что запустил начальник цеха (launches со статусом «К запуску» и далее).
- Фильтрует по узлам, заготовкам, типам обработки, приоритетам.
- Раскидывает конкретные позиции операторам на конкретные станки: одну позицию — нескольким станкам, разные количества. Формирует WorkOrder с привязкой к оператору и станку.
- Видит список активных смен операторов (кто какой станок открыл) — чтобы не назначать «в никуда».

### Оператор

- Активирует смену (выбирает станок, до двух одновременно).
- Видит назначенные ему задачи (WorkOrders): принимает в работу, фиксирует технологические переходы (описание, станок, плавка, время, количество).
- Статусы: Создан → В работе (после первого перехода) → Ожидает ОТК (все переходы выполнены).
- Уведомления о новой работе.
- История: текущий наряд, в работе, закрытые.

### ОТК (отдел технического контроля)

- Получает уведомление, когда первая деталь готова или наряд достиг определённой готовности.
- Приходит, проверяет: фиксирует принятые/брак/дефекты с причинами.
- Закрывает наряд (статус `closed`).
- При браке — возможность запуска повторного производственного цикла.

## Жизненный цикл работы (end-to-end)

1. **Загрузка номенклатуры:** Excel (VBA) → `uploadCatalog` → лист `Catalog` (24 колонки, с текстовым форматом кодов).

2. **Планирование запусков:** Нач. цеха видит дерево из `Catalog`, фильтрует, выбирает позиции, назначает на ПА → `confirmBatchLaunch` → записи в `Launches` (статус «К запуску»).

3. **Назначение операторам:** Нач. смены видит запуски, фильтрует, назначает операторов на станки → запись в `Queue` → `createWorkOrderFromQueue` → `WorkOrders` (статус `created`) + печать.

4. **Выполнение:** Оператор активирует смену (станок), видит назначенные задачи, принимает в работу (`in_progress`), заполняет технологические переходы. При первом переходе — наряд переходит в `in_progress`. Когда все переходы выполнены → статус `waiting_otk`.

5. **Контроль ОТК:** Видит готовые наряды, проверяет, фиксирует результат, закрывает → `closed` + итоги в `Закрытые`. Брак → причина, возможный повторный запуск.

6. **Печать:** При выдаче WorkOrder → `createPrintJob` в `PrintQueue` → нач. цеха видит вкладку «Печать» и отмечает «напечатано».

## Источник правды

Markdown-файлы в корне папки — это **дословные `.gs`-исходники** (не документация). Каждый `.md`-файл 1:1 маппится в `.gs`-модуль Apps Script.

Деплой выполняется вручную: файлы редактируются локально, затем копируются в редактор Apps Script и разворачиваются через веб-интерфейс (Развернуть → Управление развертываниями → Новая версия → Развернуть).

---

## Ключевые технические особенности

- Роли разграничены на уровне листа `Сотрудники` (login/password/role) и роутинга в `doGet`.
- Мастерский интерфейс и интерфейс нач. смены загружаются как **полная страница** (`?page=master-app` / `?page=shift-app`), т.к. в песочнице Apps Script inline-`<script>` через `innerHTML` не выполняется.
- Интерфейс оператора загружается как **фрагмент** (встраивается через `innerHTML` + `runInsertedScripts`).
- Событийная модель: `onEdit` в таблице вызывает `addToQueue/removeFromQueue` (Planning → Queue) и `createWorkOrderFromQueue` (Queue → WorkOrders).
- Вся серверная логика — глобально видима между модулями (Apps Script). Функции читают листы по именам колонок (`headers.indexOf`) — устойчиво к порядку.
