# Отчёт. Этап «Багфиксы: Блоки 1–5» (правки по плану HIGH+MEDIUM)

**Дата:** 04.09.2026
**Статус:** Завершён. Всё задеплоено (ручной деплой), проверено пользователем.

## Что сделано

Цикл правок из согласованного плана, разбитый на 5 блоков. Каждый блок —
самостоятельный деплой модулей с последующей ручной проверкой пользователем.

### Блок 1 — данные (HIGH-ошибки)
`ShiftUI.md`, `Launches.md`, `NaryadAPI.md`:
- ShiftUI: добавлена 13-я колонка `Launch ID` в `WorkOrders`; `issueWorkOrder()`
  сохраняет `launch.id`; `getIssuedWorkOrderQty()` группирует по `launch id`,
  пропуская `cancelled`/`rejected`.
- ShiftUI: фикс гонки данных — `getShiftWorkload()` отдаёт `issued` в каждой
  строке серверно; убраны клиентские `issuedMap`/`fetchIssued()` и устаревшее
  кэширование в `loadLaunches()`.
- Launches: `getOccupiedPANumbers()` пропускает статус «Готово» (ПА
  освобождаются); `deleteLaunch()` удаляет связанные WorkOrders по `Launch ID`;
  `updateLaunch()` запрещает менять ПА/количество вне статуса «К запуску».
- NaryadAPI: `operatorSubmitTransition()` дедуплицирует одинаковые переходы
  в окне 60 секунд (`duplicate: true`).

### Блок 2 — дашборд (M7)
`Launches.md` `getDashboardSummary()`: сводные KPI (`inWorkItems`,
`closedItems`, `totalLaunchedQty`) вынесены из вложенного цикла по ПА в
отдельный цикл по запускам — теперь считаются **один раз на запуск**, а не на
каждый ПА. Запуск на N ПА больше не завышает дашборд в N раз.

### Блок 3 — UX оператора (O1, O3)
`OperatorUI.md`, `Shifts.md`:
- O1: «Станок» в форме тех. перехода стал `<select>`, заполняется из
  `getMachines()` с автоподстановкой станка текущей открытой смены
  (`populateMachineSelect()`). Устранена несогласованность свободного ввода.
- O3: `closeShift(operatorName, shiftId)` — закрывает конкретную смену;
  у каждой открытой смены своя кнопка «Закрыть» с передачей `shiftId`.

### Хотфикс регрессии (после Блока 3)
`OperatorUI.md`: убран запрещённый `\'` в `onclick="closeShift(...)"` — заменён
на HTML-сущность `&#39;`. `\'` в inline-`<script>` ломал парсинг в
`runInsertedScripts` → `SyntaxError: Unexpected string` → «вечная загрузка
смены». Правило зафиксировано в `AGENTS.md` (раздел «Технические конвенции»).

### Блок 4 — дерево номенклатуры (M2, M4, M1)
`MasterUI.md`:
- M2: поиск сохраняет иерархию — восстанавливаются предки найденных узлов
  (восхождение по коду, логика как в `buildTree`); найденные узлы авто-раскрыты.
- M4: кнопки «📂 Развернуть всё» / «📁 Свернуть всё» в панели фильтров,
  работают через `currentTree` (рекурсивный обход).
- M1: пагинация по корневым веткам (50 веток/страницу), контрол
  «Пред. / След.», сброс на страницу 1 при смене фильтров (поиск, узел,
  операции, обновление).

### Блок 5 — прочее (L2, N2, N3)
`Launches.md`, `NaryadAPI.md`:
- L2: `expandPARange()` валидирует ввод — пустое/нечисловое/`end<start`
  возвращают `[]`, исключая «NaN»-ПА.
- N2: `updatePlanningStatusByCode()` матчит по `itemCode`; при заданной
  программе — фильтр и по ней, при пустой (наряды ShiftUI) — первая строка
  с кодом. Статус Planning теперь обновляется для ShiftUI-нарядов.
- N3: `closeNaryad()` требует `closed_by` otk-пользователя (проверка по
  `Сотрудники` через новый хелпер `isRole(user, 'otk')`); иначе — отказ.

## Как проверено

- Синтаксическая проверка изменённых модулей — `check-modules.js` PASS:
  `ShiftUI`, `Launches`, `NaryadAPI`, `OperatorUI` (+inline script), `Shifts`,
  `MasterUI` (+inline script).
- После правки UI-модулей вручную проверено 0 вхождений `\'` в `OperatorUI.md`
  (правило AGENTS.md).
- Ручные тесты пользователя по каждому блоку:
  - Блок 1: данные нарядов/запусков корректны.
  - Блок 2: дашборд — один запуск на 2 ПА в работе показывает «В работе = 1»
    (а не завышенное 2).
  - Блок 3: станок в форме перехода — выпадающий список с автоподстановкой;
    смена закрывается выбранная, а не всегда последняя.
  - Хотфикс: смена у оператора загружается (вечная загрузка устранена).
  - Блок 4: поиск низовой детали показывает её в группе (не в корне);
    развернуть/свернуть всё; страничная навигация.
  - Блок 5: проверено, что валидация/статус/роль работают (см. тест ниже).

## Что осталось

- **Полное удаление колонок Программа/Заказчик/СП** из Planning/Queue/
  WorkOrders/PrintQueue — отложено пользователем (N2 закрыт как баг-фикс,
  без изменения схемы листов).
- **Частичный статус ПА + раскрытие по изделиям** — замечание пользователя,
  не входило в цикл, отложено.
- **Настоящая серверная авторизация** — отсутствует; см. ADR-002.
- **OTK-интерфейс** (приёмка/брак/закрытие нарядов) — следующий этап.
