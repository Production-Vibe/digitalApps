# Отчёт. Этап «E2E-тестирование ролей (Playwright + сохранённая Google-сессия)»

**Дата:** 04.09.2026
**Статус:** Завершён. E2E-прогоны по всем 4 ролям — 18/18 PASS. Баг №1
(переавторизация оператора при F5) подтверждён исправленным на боевом деплое.

## Цель

Автоматически проверить развёрнутый WebApp `?page=...` на новом `/exec` URL:
- вход по каждой роли и редирект на полную страницу;
- отсутствие переавторизации при обновлении страницы (баг №1);
- отрисовку UI каждой роли.

Target: `https://script.google.com/macros/s/AKfycbzoPmk9b8lmACXpKdlAqDCY7xSLscxN5y4UoQdbW7KRjjGigKd-GG_oeAzl-28wha7KqA/exec`

## Что сделано

- Создан harness E2E в `tests/e2e/`:
  - `config.py` — URL, канал браузера, путь-профиль, учётные данные ролей (env-переопределяемые), карта лендингов.
  - `helpers.py` — frame-aware поиск селекторов (приложение рендерится внутри sandboxed-iframe
    `userCodeAppPanel`), вход по форме, скриншоты, диагностика консент-шлюза.
  - `runner.py` — общий прогон роли в чистом контексте с сохранённой Google-сессией + итоговый вывод PASS/FAIL.
  - `session_setup.py` — одноразовая привязка авторизованной Google-сессии (headless нельзя: Google-шлюз).
  - `test_operator.py`, `test_otk.py`, `test_master.py`, `test_shift.py` — ролевые сценарии.
  - `tests/e2e/.gitignore` — исключает `profile/` и `screenshots/` из контроля версий.
- Выполнена одноразовая привязка сессии (ручной вход в Google + прохождение консента в headed-браузере Playwright).
- Проведены E2E-прогоны всех 4 ролей.

## Ключевые технические находки

- **Консент-шлюз Google**: headless с чистым профилем всегда упревается в экран
  «Это приложение создано пользователем Google Apps Script» и не может войти
  (Google блокирует автоматизированный вход). Решение — один раз пройти вход в
  headed-браузере и сохранить сессию. Прогоны идут headless, но с этим
  `storage_state`.
- **Блок входа**: Playwright-сборка chromium отклоняется Google («браузер небезопасен»).
  Перешли на `channel="chrome"` (реальный установленный браузер) + stealth-флаги
  (`--disable-blink-features=AutomationControlled`, `ignore_default_args=["--enable-automation"]`,
  маскирование `navigator.webdriver`) — вход прошёл.
- **Приложение в iframe**: форма входа и весь UI ролей рендерятся внутри
  sandboxed-iframe `userCodeAppPanel` (top-frame содержит только обёртку Google).
  Селекторы ищутся по всем фреймам (frame-aware), а не в главном документе.
  Именно это сначала мешало захвату сессии (скрипт искал `#login` только в top-frame).
- **Изоляция прогонов**: длинный persistent-профиль накапливает состояние между
  ролями (автологин). Перешли на чистый контекст на прогон, сея только
  `storage_state.json` (Google-сессия), с пустым localStorage приложения →
  форма входа стабильно показывается в каждом прогоне роли.

## Найденные баги и результаты тестирования

### Баг №1 — переавторизация оператора при обновлении страницы (исправлен)

- **Симптом:** оператор после входа попадал на `?page=login` (фрагмент-инъекция
  `document.body.innerHTML = getOperatorPageFragment(...)`). По `F5` браузер
  запрашивал логин заново — оператор терял сессию/контекст.
- **Причина:** оператор был единственной ролью, аутентифицируемой через
  фрагмент без смены URL. master/shift/otk переходят на полные страницы
  (`?page=...&name=...`), поэтому refresh их сохранял, а оператора — нет.
- **Фикс:** `modules/Auth.md` — оператор после логина переходит на полную
  страницу `?page=operator&name=...&id=...`, QR-`id` сохраняется через
  `window.__qrNaryadId`. Galaxy-галка «запомнить» больше не обязательна.
- **Статус:** исправлен, коммит `5022dc9` (тег `v0.2-e2e`); подтверждён E2E на боевом деплое
  (URL полной страницы + F5 без возврата на форму входа).

### Прочие баги, найденные в ходе E2E-работ

Не выявлено. Ролевые прогоны прошли без ошибок приложения; в console — только
штатные warning песочницы Google.

### Подтверждение фикса бага №1

- После логина оператор находится на **полной странице**:
  `.../exec?page=operator&name=%D0%98%D0%B2%D0%B0%D0%BD%D0%BE%D0%B2+%D0%98.+%D0%98.`
- `F5` (`page.reload`) не возвращает форму входа — проверка `F5 не перебрасывает на
  форму входа` → PASS. Галка «запомнить» оператору больше не обязательна.

## Как проверено

- `python -m py_compile tests/e2e/*.py` — все модули компилируются.
- Каждый ролевой тест запускается отдельно: `python tests/e2e/test_<role>.py`.
- Вывод по каждой проверке `[PASS]/[FAIL]`, в конце — сводка. Скриншоты и лог консоли собраны.
- Итоговые прогоны (последний проход): operator **6/6**, otk **4/4**,
  master **4/4**, shift **4/4** — **18/18 PASS**, консоли без ошибок.

Повторяемый пошаговый алгоритм запуска (сессия, команды, грабли) зафиксирован в
`docs/testing/e2e-runbook.md`.

## Что осталось / замечания

- Визуально скриншоты оператора/мастера/ОТК/shift не были просмотрены моделью
  (нет поддержки изображений) — подтверждение отрисовки получено **по тексту из
  фреймов**, что надёжнее пиксельного просмотра.
- Глубокие бизнес-флоу (полный жизненный цикл наряда через ОТК/оператора,
  выдача shift → оператор → ОТК → закрытие) текущими сценариями **не покрыты** —
  только вход + рендер + редирект + refresh. Полный E2E-цикл данных — следующий
  этап (опционально, требует стабильных тест-данных в таблице).
- Учётные данные ролей захардкожены как fallback в `config.py` (тестовые: operator/123 и т.п.);
  для продакшена переопределяются env (`ND_LOGIN_*`, `ND_PASSWORD_*`, `ND_NAME_*`).
- `profile/` содержит Google-сессию и **исключён из git** (`.gitignore`).
