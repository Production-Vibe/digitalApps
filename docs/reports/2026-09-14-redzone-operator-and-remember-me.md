# Отчёт этапа — красная зона оператора + «Запомнить меня» (14.09.2026)

> Цель этапа: устранить критические несоответствия UI, замеченные при живом
> аудите всех ролей, прежде чем двигаться в новую реализацию. Проверено против
> Docker-стенда (localhost:3000).

## Что было найдено (красная зона)

- `server/src/views/operator.ejs` — форма «Открыть смену» рендерилась **только при
  пустой истории смен** (`renderShifts`: `if (!shifts || shifts.length === 0)`).
  Любая закрытая смена (в т.ч. smoke-хвост `СМ-260911-093821` от 11.09) скрывала
  форму навсегда → оператор не мог открыть новую смену → не мог принимать наряды →
  роль operator и весь поток «выдача → оператор → ОТК» были недостижимы.
- Авторизация: токены/`user` хранились в `localStorage` безусловно; «запомнить
  меня» отсутствовало как понятие; «Выйти» на страницах вызывал `localStorage.clear()`
  (inconsistent после split хранилищ).

## Что сделано

### 1. Фикс оператора (баг)
- `operator.ejs#renderShifts` переписан: форма «Открыть смену» + `#openMachine`
  показываются, когда **нет открытой смены**; таблица истории смен рендерится
  всегда. Бэкенд-инварианты (`/api/shifts/open`) не менялись.

### 2. «Запомнить меня» (авторизация)
- `login.ejs`: чекбокс «Запомнить меня» (по умолчанию включён), подключён `/api.js`.
- `server/src/public/api.js`: добавлены `tokenStore()` (выбор хранилища по флагу
  `remember`), `saveSession()`, `clearSession()`, `logout()`. `api()`/refresh/`getCurrentUser()`
  читают токены из выбранного хранилища. Галка → `localStorage` (переживает
  закрытие браузера), снята → `sessionStorage` (вход при каждом открытии вкладки).
- Кнопки «Выйти» всех ролей (`master-app`, `operator`, `otk-app`, `shift-app`)
  переведены на общий `logout()` (чистит оба хранилища).
- Решение принято с пользователем: проф-эволюция — refresh-токен в
  `httpOnly`-cookie со sliding-экспирацией — отложена в этап безопасности.

### 3. Деплой
- `docker compose up -d --build` в `server/` — образ `server-app` пересобран,
  изменения на live-стенде (localhost:3000 + Tailscale Funnel).
- БД приведена в чистый вид: `DELETE FROM "Shifts" WHERE status = 'closed'`
  (smoke-хвост удалён; данных больше нет — всё по нулям).

## Как проверено

- `cd server && npm run build` + `npm run check` — **PASS**.
- Штатный E2E (`tests/e2e/`) на `localhost:3000` — **18/18 PASS**
  (operator 6, otk 4, master 4, shift 4).
- Целевой Playwright-probe — **14/14 PASS**:
  - пустая история → форма «Открыть смену» видна;
  - открытие смены (Т1-1) → «Открыта», форма скрыта;
  - закрытие → «Закрыта» в таблице **и** форма снова видна (основной кейс бага);
  - remember ON → токены в `localStorage`, в `sessionStorage` пусто;
  - remember OFF → токены в `sessionStorage`, в `localStorage` пусто, флаг `remember=0`;
  - «Выйти» → оба хранилища пусты, редирект на `/login`.
- Тестовая смена из probe удалена после прогона.
