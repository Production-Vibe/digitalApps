# Этап 10 — полный E2E бизнес-цикла (17.09.2026)

> Отчёт о завершении этапа: сквозной автоматизированный прогон всего
> производственного потока через UI всех 4 ролей (`shift` выдаёт → оператор →
> ОТК → rework → закрытие → аналитика мастера). По ходу прогона найден и
> устранён реальный серверный баг генерации ID. Этап = 10 по нумерации STATUS.md.

## Что сделано

### Тест `tests/e2e/test_bizcycle.py` (new)
- Единый контекст-в-контекст прогон: master создаёт 2 запуска («Гидробак»,
  qty 10/20, ПА `E2E-71`/`E2E-72`) → operator открывает смену на Т1-1 →
  shift выдаёт 2 наряда (Т1-1/Т1-2, первый активный оператор из
  `/active-operators`) → operator happy-фаза (оба наряда «В работу» + переход) →
  ОТК фаза 1 (наряд №1 проверить+закрыть, наряд №2 на доработку) → operator
  rework (правка → новый переход → `waiting_otk`) → ОТК фаза 2 (проверка +
  закрытие №2, очередь пуста) → master аналитика (Сводка/Номенклатура/Отчёты
  видят данные) → SQL-cleanup.
- `clean_test_data()` удаляет тестовые артефакты в FK-порядке
  (`Transitions → ClosedOrders → PrintQueue → WorkOrders → Launches → Shifts`),
  плюс `Notification` по `LIKE`; каталог и «живые» смены пользователя не трогает.
- Устойчивость: `operator_run` перекликивает «Обновить» (до 5 попыток),
  `wait_detached` ждёт ухода строки после перехода, OTK rework-фаза учитывает
  2 завершённых перехода (`.first` для «Проверить»), `make_dialog_handler`
  отвечает на оба `prompt()` (`Принято` / `Брак`).

### Серверный фикс `server/src/lib/id.ts` (real bug)
- **Симптом:** при выдаче двух нарядов в одну секунду второй `/issue` падал
  `500` («Повторная запись уже существует», Prisma P2002) — ID
  `Н-yyMMdd-HHmmss` имеет секундную метку, две записи в одну секунду
  конфликтовали по PK.
- **Фикс:** общий `stamp(prefix)`, который при повторе секунды добавляет суффикс
  `-N` (`Н-260917-072540`, `Н-260917-072540-2`, …). Обычный формат не меняется,
  уникальность гарантирована в пределах процесса. Применён к `generateNaryadId`,
  `generateLaunchId`, `generateShiftId`.

### Ужесточение тестовых локаторов
- `naryad_row()` — поиск строки наряда **точной** первой ячейкой
  (`td` с текстом ровно `Н-...`), а не `has_text=<номер>`: при суффиксе `-2`
  подстрока совпадала с двумя строками и роняла strict-mode. Использовать в
  `operator_run`, `otk_check_and_close`, `otk_send_to_rework`, `wait_detached`.
- `wait_selector` получил параметр `state`; для `<option>` внутри закрытого
  `<select>` ждать сам `<select>` (иначе `visible`-ожидание висит таймаут).
