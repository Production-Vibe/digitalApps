# Этап 15 — смена боевых паролей + защита seed от их сброса при деплое

Дата: 22.09.2026. Контур: `main` (Node/Express + EJS + Prisma + PostgreSQL).

## Что сделано

Один боевой пароль (длиной ≥8, известен пользователю; в git/отчёты не
пишется) задан всем 5 сидовым аккаунтам — `admin`, `master`, `shift`,
`operator`, `otk` — на **обоих контурах** БД: локальный `MOSD`
(`localhost:5432`) и стендовый `digital_narad` (host-порт `5434`).

Серверные правки:

1. `server/scripts/set-passwords.ts`:
   - добавлен `import 'dotenv/config'` первой строкой — скрипт сам грузит
     `server/.env` (раньше без `DATABASE_URL` в окружении падал с «Environment
     variable not found»; `src/lib/prisma.ts` на dotenv не завязан);
   - логин `admin` добавлен в список (`['admin', 'master', 'shift', 'operator',
     'otk']`) — до Этапа 14 администратора в скрипте не было.
2. `server/prisma/seed.ts` (`seedEmployees`): upsert переведён на `update: {}` —
   **пароль задаётся только при создании аккаунта** (`create`). Существующие
   логины seed не трогает вовсе (пароль/роль/ФИО не перезаписываются). Ранее
   `update: { password: hash }` сбрасывал пароли к `123` при каждом деплое
   (контейнер стартует с `prisma migrate deploy && prisma db seed`).

На `MOSD` логин `admin` отсутствовал (сид после Этапа 14 там не прогонялся) —
создан с боевым паролем через временный скрипт (`.tmp-create-admin.ts`,
bcrypt-hash нового пароля; удалён после выполнения).

Деплой: образ пересобран (`docker compose up -d --build` в `server/`) — фикс
seed попал в образ; контейнер стартовал (migrate deploy + db seed + node),
`/health` → `{status:'ok', db:'connected'}`.

## Доп. прогон: авторизация / регистрация / защита входа / деактивация

Проверена цепочка auth живого стенда новым скриптом
`tests/e2e/test_auth_flow.py` (API через Playwright `APIRequestContext` — куки
общего контекста браузера; единственный UI-кейс — форма регистрации):

- **Авторизация:** вход 5 боевых ролей новым паролем → 200 + accessToken + кука
  `nd_refresh`; старый `123` → 401; `refresh`/`session` → 200; `logout` чистит
  куку → `session` 401; `GET /api/me` с Bearer (admin) → role admin.
- **Регистрация:** роль в теле (`"otk"`) игнорируется → всегда `operator`;
  авто-вход; дубль логина → 409; валидации → 400: пустой логин, логин >40, ФИО
  одним словом, пароль <6, несовпадение паролей; UI: таб «Регистрация» на
  `/login` → редирект на `/operator` → «Выйти» → `/login`.
- **Защита входа:** 5 неудачных попыток на тестовом логине `nobody-probe` → 401,
  6-я → **429** (блок на 15 мин ложится только на синтетический логин).
- **Деактивация:** admin `PATCH isActive=false` тестовому оператору → его вход
  403, session/refresh 401, скрыт из `GET /api/employees`; реактивация → 200 →
  вход 200; сам-отключение admin → **400**.
- Итог: **33/33 PASS**; cleanup удалил тестовых операторов SQL-ом (Employees=5),
  бизнес-таблицы стенда не тронуты.

Грабли нового теста: у `APIRequestContext` нет `request(...)` — только
`fetch(url, method=…)`; тестовые логины снабжаются случайным суффиксом, чтобы
повторные прогоны в ту же минуту не упирались в коллизию (409).

## Грабли, зафиксированные по ходу

- `tests/e2e/config.py._cred()` возвращает `None` (→ fallback `123`), если не
  задана **пара** `ND_LOGIN_*` + `ND_PASSWORD_*`. Задание только пароля молча
  даёт «Неверный логин или пароль» на боевом стенде. В `e2e-env.ps1` заданы и
  логины, и пароли, и ФИО всех 5 ролей.
- PowerShell-цитирование в однострочных `npx tsx -e` съедает кавычки — для
  проверок использовались временные tsx-файлы (удалены).
