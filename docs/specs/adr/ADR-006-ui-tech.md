# ADR-006: Технология наладки интерфейса (после Этапа 3)

Статус: принято (14.09.2026).

## Контекст

Требуется «наладка всего интерфейса»: визуальная консистентность, единые
паттерны (панели, таблицы, бейджи, пустые состояния), mobile-качество (доступ с
телефона через Tailscale Funnel) и графики на экранах мастера. Рассматривались:

- **React SPA (Vite + TS)** — полная переплатформа клиента.
- **Остаться на Express+EJS+Vanilla** и структурировать фронтенд.
- Применение «MCP-сервиса» как runtime — нерелевантно: MCP — это протокол
  инструментов для агента (в проекте уже есть Playwright/webapp-testing,
  скиллы web-design/frontend-design), а не рантайм приложения.

## Решение

Остаёмся на **Express + EJS + Vanilla JS** с двумя структурирующими дополнениями:

1. **Дизайн-система на CSS-токенах** в `server/src/public/styles.css`
   (направление «Пульт цеха»: тёмная шапка-планка, светлые рабочие панели,
   семантика статусов цветом «светофор цеха», табулярные цифры, моноширинные
   коды/ID, `focus-visible`, `prefers-reduced-motion`, mobile-first).
2. **Общие JS-помощники** в `server/src/public/ui.js` (рендер карточек/бейджей,
   пустых состояний, графических холстов), чтобы убрать дубли инлайн-логики по
   страницам.
3. **Графики — Chart.js**, вендорный файл `server/src/public/vendor/chart.umd.min.js`
   (без CDN: стенд и локальная сеть могут быть без внешнего интернета).

## Последствия

- Никакого сборщика фронтенда: статика из `public/`, вью — EJS; Docker
  по-прежнему копирует `src/views` и `src/public` в `dist/`.
- Серверная правка минимальна: в `/api/analytics/dashboard` добавляется
  `reports.daily` (временной ряд закрытых нарядов за период) для timeline.
- React SPA откладывается: вернуться при значительном росте числа экранов,
  сложных виджетов или командной разработке UI.
