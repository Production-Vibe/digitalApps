# ADR-012: Длинная работа через handoff + restart вместо lossy-компакшена

Статус: принято (Accepted, 16.10.2026).

## Контекст

Длинная задача в opencode упирается в контекст сессии. Исторически проблема
проявилась как деградация повторными компакшенами: накопление шума и
галлюцинаций, потеря «почему» (диагноз и попытка частичного лечения —
ADR-010: durable-память и контракт приёмки брифа в контуре «два терминала»).
Команда `/handoff` (Этап 24) дала переносимый бриф вместо lossy-compaction,
но оставалась ручной: перенос делал человек, автоматики возобновления не было,
а контур делегирования «планировщик → MCP-мост → исполнитель» закрыт удалением
(ADR-011, Этап 26).

Пользователь принял решение (15–16.10.2026): длинную работу держать в цикле
**исполнение → handoff → restart → исполнение** — каждая итерация это свежая
сессия с чистым контекстом, а нить переносится файлом брифа на диске, а не
памятью движка. Задача цикла — ту же проблему закрыть на уровне протокола, а не
ещё одного инварианта внутри одной сессии.

## Решение

1. **Контракт — `instructions/session-loop.md`** (подключён в
   `opencode.json → instructions`, читается каждой сессией). Описывает:
   триггеры handoff (контекст ≥ порога, граница фазы, вопрос пользователю),
   YAML-frontmatter брифа (`loop: continue|done|blocked`, `iteration`,
   `approved_plan`, `next_action`), resume-режим (без повторного
   pre-approval, только утверждённый scope), семантику остановки (ход без
   записанного брифа = потеря нити) и контракт драйвера.
2. **Напоминание о пороге — плагин `.opencode/plugin/handoff-threshold.ts`.**
   Хук `experimental.chat.messages.transform`, только orchestrator: при
   доле контекста ≥ `ND_HANDOFF_THRESHOLD` (дефолт 0.58) дописывает в конец
   последнего user-сообщения просьбу сделать handoff и завершить ход.
   Источник — usage токенов модели, документированный фолбэк по объёму;
   идемпотентно и аддитивно к argos, ошибки гасятся.
3. **Автоматизация — драйвер `.opencode/loop/ralph-loop.ps1` +
   `run-agent-loop.cmd`.** На каждую итерацию — свежая сессия
   `opencode run --agent orchestrator --auto`; драйвер читает frontmatter
   свежего брифа и `.opencode/loop/state.json` (ведёт сам), решает
   resume/cold, держит лимит итераций и жёсткий таймаут с kill-on-hang,
   останавливается по `done`/`blocked`/лимиту/таймауту/отсутствию брифа
   (коды выхода 0–4). Режим `-Dry` симулирует переходы в песочнице, не трогая
   живую нить; runtime (логи, `state.json`, `dry-run/`) — gitignored.
4. **Ритуал старта читает состояние цикла.** Пункт 0 `AGENTS.md` дополнен:
   у свежего брифа читается frontmatter цикла и, если цикл ведётся,
   `.opencode/loop/state.json` — по ним различаются resume и холодный старт.
5. **Граница применимости.** Цикл — инструментальный контур
   engineering-работ (`instructions/`, `.opencode/`); `server/**`, БД и
   демо-пароли не затрагиваются; реальный прогон (`--auto`) — только по
   явному согласию пользователя; деплой остаётся отдельным решением.

## Альтернативы (рассмотрены и отклонены)

- **Одна долгоживущая сессия с компакшеном движка** — отклонено: компакшен
  lossy по определению (шум, галлюцинации, потеря рассуждений), это та самая
  проблема, под которую уже были написаны ADR-010 и команда `/handoff`.
- **Продолжение той же сессии (`opencode --continue`) между итерациями** —
  отклонено: накопленная история противоречит идее рестарта, компакшен
  включится снова; задача цикла — свежие сессии.
- **Память в виде prose-заметок без машиночитаемого контракта** — отклонено:
  без frontmatter (`loop`/`iteration`/`approved_plan`) драйвер не отличает
  resume от cold и не видит `done`/`blocked` → слепое продолжение или ложные
  стопы. Frontmatter делает состояние проверяемым (тот же приём, что и
  контракт приёмки брифа из ADR-010).
- **Только ручной перенос через `/handoff`, без драйвера** — оставлено как
  базовый и штатный режим работы, но не как единственный путь длинной задачи:
  ручной режим не даёт лимитов итераций, таймаута, kill-on-hang и единых кодов
  выхода для наблюдения/автоматизации.
- **Вместо цикла — диспатч подзадач argos** — не отклонено, а разведено:
  argos (ADR-011) параллельно делегирует задачи специалистам, session-loop
  ведёт последовательную длинную линию одной задачи; они совместимы — драйвер
  зовёт orchestrator, у которого argos-тулзы доступны.

## Последствия

- Нить цикла живёт на диске (`.opencode/handoff/`, `.opencode/loop/state.json`,
  оба gitignored): падение/закрытие сессии не теряет работу; источник правды по
  состоянию проекта остаётся `STATUS.md` (бриф обязан с ним сверяться).
- Каждая итерация платит пере-чтением инструкций (AGENTS/STATUS/architecture
  инжектятся автоматически) — выигрыш в качестве контекста против этой
  оплаты.
- Зависимость от `--auto`: реальные прогоны — по согласию; deny-правила
  permissions при этом остаются в силе.
- Порог плагина пока подтверждён probe на синтетических сообщениях, живого
  срабатывания на настоящем usage не было — ожидается наблюдение на первом
  длинном ходе (порог настраивается env).
- Документация: контракт — `instructions/session-loop.md`, спека —
  `docs/specs/agent-loop.md`, ритуал старта и control plane в `AGENTS.md`,
   запись этапа в `docs/reports/STATUS.md`; верификационные доказательства —
   `.artifacts/verification/{handoff-threshold-verification,ralph-loop-dry-run}.md`,
   полный прогон драйвера 16.10 (argv-стаб, ветка таймаута/kill → exit 4) —
   `.artifacts/verification/session-loop-driver-dry-run.md`.
- `server/**` не менялся — это чисто инструментальный контур.
