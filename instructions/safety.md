# Safety — правила безопасности и деплоя «ЦифровойНаряд»

Эти правила не «конвертируются» и действуют в любой сессии. Они подключены
проектом через `opencode.json → instructions`, а здесь продублированы кратко для
быстрого восприятия. Полный контракт — `AGENTS.md`.

## Секреты и сессии
- Никогда не коммитить секреты: `server/.env`, `tests/e2e/profile/`
  (`storage_state.json`), `tests/e2e/.secrets/`, `.playwright-mcp/`, cookies и пр.
  исключены `.gitignore` — не добавлять их в staging.
- Не хардкодить API-ключи/пароли в `opencode.json` или конфигах — только env или
  исключённые файлы.
- `server/src/config.ts` имеет dev-дефолты (`JWT_SECRET=dev-secret`,
  `VBA_SECRET=dev-vba-secret`) — при публикации обязаны прийти из `server/.env`.

## Деплой — Docker
- Деплой — сборка образа + `docker compose up`: `prisma migrate deploy` +
  `prisma db seed` + `node dist/app.js`. Без clasp, без ручного копирования в
  WebApp. Легаси-манифест GAS-деплоя живёт только в ветке `google-apps`.
- Не деплоить без явного согласия пользователя и без предупреждения, что меняется.
  По завершении этапа деплоя говорить «тестируй».
- Перед деплоем: `npm run build` + `npm run check` (см. `instructions/verification.md`).

## Безопасность (перед публикацией)
- Сменить dev-секреты и dev-пароли (`123`) на реальные; роли-«боевые» логины —
  это сид, не прод.
- Заложить rate-limiting на `/login`, https, политику относительно
  `localStorage`-токенов (XSS-захват) — до внешнего доступа к сервису.

## Границы
- НЕ править сгенерированные артефакты/миграции (`server/prisma/migrations/*`)
  напрямую — миграции создаются через `prisma migrate dev`.
- НЕ удалять модели/функции, на которые ссылается другой модуль (кросс-ссылки
  через Prisma/маршруты).
- НЕ переименовывать файлы-модули сервера без обновления README и роутинга
  `server/src/app.ts`.
- Push в удалённый репозиторий — только с явного разрешения пользователя.
