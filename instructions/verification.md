# Verification — обязательные проверки «ЦифровойНаряд»

Правила верификации: ничего не считать готовым без фактического подтверждения
(см. также скилл `verification-before-completion`).

## Обязательность скиллов
- Любая задача начинается с загрузки профильного скилла по фазе (таблица
  «Скиллы — обязательный триггер по фазе» в `AGENTS.md`): планирование →
  `brainstorming`/`writing-plans`, отладка → `systematic-debugging`, UI →
  `web-design`/`frontend-design`, выполнение кода → доменный скилл.
- Любая завершённая работа проходит `verification-before-completion`: никаких
  «предположительно всё ок» без запущенных проверок и их вывода.

## Перед деплоем
- Прогнать сборку и синтаксическую проверку:
  - `cd server && npm run build` — TypeScript-типы (`tsc`);
  - `npm run check` — `node --check dist/app.js`.
- При проверке dev-контура — `npm run dev` против локального `MOSD`, smoke:
  `GET /health` → `{status:'ok', db:'ok'}`.

## E2E (Playwright)
- Прогоны ролей по `docs/testing/e2e-runbook.md`: operator/otk/master/shift
  против `localhost:3000` (JWT-логин через `/login`, `localStorage`).
- Эталон: operator 6/6, otk 4/4, master 4/4, shift 4/4 — итого 18/18 PASS.
- Подтверждением отрисовки служит текст из страниц (не только скриншоты).
- Google-сессия больше не нужна: E2E проходит через JWT-авторизацию нового стека.

## Сообщения коммитов (стандарт)
- Сообщения — **на русском**, формат Conventional-ish: `<тип>: <что> (<зачем>)`.
  Типы: `feat`, `fix`, `test`, `docs`, `refactor`, `chore`.
- Один логический этап = один коммит (этап → коммит, без дробления правок одного
  признака на мелочи). Избегать пустых сообщений («Фикс», «Refactoring»).
- Документацию (отчёты/specs) не смешивать с кодом в одном коммите без нужды.

## Завершение этапа
- Обновить живое состояние: `docs/reports/STATUS.md` (последний этап, открытые
  баги, следующий шаг, URL деплоя, коммиты) — обязательный DoD.
- Датаированные отчёты — в `docs/reports/` (детализация этапа).
- Заключительный коммит этапа пометить git-тегом `v<N>-<этап>` (напр.
  `v0.3-opencode-layer`). Тег — «этап завершён в git», не «в проде» (деплой
  рассинхронизирован с тегом, контур деплоя — Docker).
- История: `git commit --amend`/rebase истории и force-push — только с явного
  согласия пользователя (правило push в opencode.json/AGENTS.md).

## Правило доказательств
- Не говорить «сделано / работает / прошло» без запущенных проверок и их вывода.
- Если проверку нельзя запустить — честно указать почему и что не проверено.
