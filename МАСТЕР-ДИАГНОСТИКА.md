# МАСТЕР — ДИАГНОСТИКА И ПЕРЕЗАПУСК
(полный чек-лист «почему вечная Загрузка…» и как починить)

> Ключевой вывод: элементы мастера (`planningList`, `searchInput`) НЕ найдены
> на странице `?page=master-app`. Значит грузится НЕ страница мастера, а какая-то
> другая (обычно — старый код входа). Почти всегда причина = **открыт старый URL
> или старый deployment со старым кодом**, где `color case 'master-app'` рендерит
> не то / вообще отсутствует.

---

## ШАГ 1. Проверка, какая страница реально загружена
Открыть страницу мастера (это тот URL, где «Загрузка…»), F12 → Console, вставить:

```js
document.body.innerHTML.slice(0,300)
```

Выполнить и прислать результат.

```js
Array.from(document.scripts).map(s => (s.textContent||'').slice(0,60)).join(' ||| ')
```

```js
document.getElementById('planningList') ? 'planningList есть' : 'planningList НЕТ'
```

```js
document.getElementById('login') ? 'это страница ВХОДА' : 'не форма входа'
```

---

## ШАГ 2. Проверка, что бандл привязан к НОВОЙ таблице
Открыть **новую** таблицу (не удалённую) → Расширения → Apps Script.
Посмотреть URL вкладки скрипта:

```
/d/<SCRIPT_ID>/edit
```

Он должен совпадать с:

```
12g5YaTk6fKmpA7UZLKcG42LBGlZHUHRpnKOSuIr7EBg
```

- Совпадает  -> бандл тот, что надо, идём дальше.
- НЕ совпадает -> вы открываете скрипт/таблицу СТАРОЙ, которую удалили. В этом
  и дело: там старый код. Нужно работать ТОЛЬКО с новой таблицей.

---

## ШАГ 3. Проверка и обновление deployment (самое важное)
В Apps Script (новая таблица, правильный бандл):

1. Верхняя панель → **Развернуть → Управление развертываниями**.
2. У активной записи (со значком «/exec») посмотреть: **версия** и **«новый
   редактор» / источник**.
3. Если версия СТАРАЯ (не последняя) → обновить:
   - «Развернуть → Управление развертываниями» → нажать значок «✎» (изменить)
     → **Версия: Новая версия** → Сохранить.
4. Если активного деплоя нет → создать заново:
   - **Развернуть → Новое развертывание**.
   - Тип: **Веб-приложение**.
   - «Выполнять от имени»: ваша учётка.
   - «Кто имеет доступ»: **Любой** (или «Любой в вашей организации»).
   - **Развернуть** → разрешить доступ (если спросит) → скопировать НОВЫЙ
     `/exec` URL.

## ШАГ 4. Открыть ТОЛЬКО по НОВОМУ /exec URL
Скопировать свежий `/exec` URL из Шага 3 (полностью новый, не старую закладку!).

В адресную строку браузера (в новой/инкогнито вкладке) вставить:

```
https://script.google.com/macros/s/НОВЫЙ_ID/exec?page=master-app&name=Козлов+К.К.
```

Если приложение требует логин — сначала зайти по обычно:

```
https://script.google.com/macros/s/НОВЫЙ_ID/exec
```

войти, затем открыть мастер.

После этого в консоли страницы мастера:

```js
typeof loadCatalog
typeof enrichCatalog
typeof renderTree
```

Ожидаемо `"function"` (не `undefined`).

---

## ШАГ 5. Если всё ещё «undefined» на НОВОМ URL — проверить, что в деплое новые .md
В Apps Script (новая таблица) открыть файлы проекта и убедиться, что в них
последние правки:

- `Auth.md`  -> в `doGet` есть:

```js
case 'master-app':
  html = renderMasterAppPage(name);
  break;
```

  и в `checkAuth` возвращается `execUrl`.

- `MasterUI.md` -> есть `renderMasterAppPage` (оборачивает фрагмент в полный HTML)
  и `loadCatalog`.

Оба файла должны быть в составе активного deployment.

---

## ШАГ 6. Финальная проверка результата
После логина мастер открывается по нативному URL:
`.../exec?page=master-app&name=...`

В консоли:

```js
document.getElementById('planningList') ? 'planningList есть' : 'planningList НЕТ'
```

Должно быть `planningList есть`, а `typeof loadCatalog` = `"function"`.

Если это так, но дерево всё равно «Загрузка…» — тогда смотрим `getCatalogForMaster`
(открыть в консоли серверной части или проверить Catalog, колонку «Код»).
