### КОНТЕКСТ ПРОЕКТА

**ЦифровойНаряд** — система управления производством подъёмных агрегатов (ПА). Полный цикл: от выгрузки номенклатуры из Excel до выдачи задач операторам и учёта запусков на конкретные ПА.

**Стек:** Excel (VBA) + Google Таблицы + Google Apps Script WebApp.

---

```
EXCEL (VBA)

```

### ЧТО УЖЕ РАБОТАЕТ В MasterUI.gs

**Страница:** `getMasterPageFragment(name)` — HTML + CSS + JavaScript.

**Элементы интерфейса:**

1. **Фильтр по узлам** — выпадающий список, строится на клиенте из дерева Catalog (`filterUnit`)
2. **Фильтр по типам обработки** — 9 чекбоксов (Резка, Термо, Плазма, Токарная, Фрезерная, Сверлильная, Слесарная, Гибка, Покрытие), логика `every` (все выбранные)
3. **Поиск** — строка с мгновенным фильтром по коду/наименованию
4. **Дерево позиций** — группы → сборки → детали с вложенностью по иерархии кодов
5. **Чекбоксы** — выбор позиций для массовых действий
6. **Модалка запуска на ПА** — при «🚀 В запуск» открывается окно: номера ПА, проверка занятых (`getOccupiedPANumbers`), режим количества (авто = «Кол-во на родителя» × число ПА, либо вручную)

**Функции JavaScript в MasterUI.gs:**
- `loadCatalog()` — загрузка данных из Catalog через `getCatalogForMaster()` + обогащение (`computeType`/`computeUnit` на клиенте)
- `loadUnits()` — список узлов для фильтра, строится на клиенте из `allData`
- `buildTree(items)` — построение дерева из плоского списка
- `renderTree()` — отрисовка с учётом поиска и фильтров
- `renderNode(node, level)` — рекурсивная отрисовка одного узла
- `computeType(code)` / `computeUnit(code, map)` — тип/узел из кода на клиенте
- `getStatusClass(status)` — используется только в «Загрузке ПА» (из Launches)
- `toggleTreeNode`, `toggleAssemblyKids` — сворачивание/разворачивание
- `toggleAssembly`, `toggleDetail` — чекбоксы (идентификация по `code`, каскад вниз)
- `updateBatchBar`, `clearSelection` — массовый выбор
- `openLaunchModal(btn)` — открывает модалку запуска одной позиции
- `onQtyModeChange`, `recalcAutoQty`, `updatePaInfoFromInput` — авто/ручное количество
- `closePaModal`, `checkPaNumbers`, `parsePaInput`, `confirmPaLaunch` — логика модалки ПА (шлёт массив `{code,name,unit,qty}` в `confirmBatchLaunch`)
- `batchSetStatus(status)` — массовый запуск через модалку ПА
- `onSearch`, `clearSearch`, `applyOpFilter`, `clearOpFilter` — фильтры

**Серверные функции для MasterUI.gs (в PlanningAPI.gs):**
- `getCatalogForMaster()` — читает Catalog по именам колонок → `row,code,name,designation,qtyPerParent,material,grade,weight,cutting..coating,priority`
- `confirmLaunchByCode(itemCode, itemName, unit, qty, paNumbers)` — создаёт запись в Launches
- `confirmBatchLaunch(items, paNumbers)` — массовый запуск, `items=[{code,name,unit,qty}]`

> Примечание: `unit`/`type`/`qty` вычисляются на клиенте (см. `computeUnit`/`computeType`/`enrichCatalog`), сервер не возвращает статусы — дерево = чистая номенклатура Catalog. Лист `Planning` физически сохранён, но нач. цехом не заполняется и не читается (метрики статусов переходят в будущий модуль аналитики).

**Серверные функции Launches (в Launches.gs):**
- `createLaunch(itemCode, itemName, unit, qty, paNumbers, status, launchType, reason, relatedId)`
- `getLaunches()`
- `getOccupiedPANumbers()` — возвращает объект занятых ПА
- `getPALoadSummary()`
- `expandPARange(str)` — разворачивает "001-005" в массив

### 2. Критически важные правила для JavaScript внутри шаблонных строк

**ЗАПРЕЩЕНО:**
- Использовать `\n`, `\t`, `\r` в комментариях внутри шаблонной строки
- Использовать экранированные кавычки `\'` в onclick-атрибутах
- Использовать `\`` (обратные кавычки) внутри шаблонной строки
- Писать `// комментарий с \n` — это ломает парсинг

**ПРАВИЛЬНО:**
- Для onclick: передавать `this` + data-атрибуты
  ```javascript
  // ✅ Верно
  html += '<span onclick="myFunc(this)" data-id="' + value + '">...</span>';
  
  // ❌ Неверно
  html += '<span onclick="myFunc(\'' + value + '\')">...</span>';
  ```
- Для переносов строк в пользовательских сообщениях: использовать конкатенацию строк
  ```javascript
  // ✅ Верно
  let msg = 'Строка 1' + String.fromCharCode(10) + 'Строка 2';
  
  // ❌ Неверно
  let msg = 'Строка 1\nСтрока 2';  // Внутри шаблонной строки сломается
  ```
- Комментарии писать без спецсимволов: "перенос строки", "табуляция", "обратный слеш"

## 📝 СКИЛЛЫ, ИЗВЛЕЧЁННЫЕ ИЗ ОШИБОК ЭТОЙ СЕССИИ

---

### 1. **Сериализация данных через `google.script.run`**

**Проблема:** Функция возвращала `null` через веб, хотя вручную работала.

**Причина:** Объект `Date` (созданный через `new Date()`) **не сериализуется** корректно при передаче через `google.script.run`. Это приводит к тому, что вся функция возвращает `null`.

**Решение:** Всегда преобразовывать `Date` в **String** перед возвратом:
```javascript
createdAt: String(row[8])  // ✅ Правильно
createdAt: row[8]           // ❌ Ломается через веб
```

**Правило:** Любые не-примитивные типы (Date, объекты Spreadsheet, Range) должны быть преобразованы в String/Number/Boolean/Array перед возвратом из серверной функции.

---

### 2. **Бесконечная рекурсия**

**Проблема:** `getLaunchRecords()` вызывает `getPAGridData()`, которая вызывает `getLaunchRecords()` — переполнение стека.

**Решение:** Функции, которые читают один и тот же лист, должны **читать лист напрямую**, а не вызывать друг друга.

**Правило:** Никогда не создавайте цепочки вызовов, которые могут замкнуться. Если функция A вызывает B, то B не должна вызывать A.

---

### 3. **Дублирование функций**

**Проблема:** Две функции с одинаковым именем `showLaunchesForItem` — вторая переопределяет первую, вызывая путаницу.

**Решение:** Перед добавлением функции проверять, нет ли уже такой же.

**Правило:** Ctrl+Shift+F → поиск по имени функции → убедиться, что нет дублей.

---

### 4. **Debug-алерты и отладка**

**Проблема:** Слишком много debug-алертов загрязняют код.

**Решение:** Использовать временные алерты **точечно**, сразу удалять после нахождения проблемы.

**Правило:** После отладки — всегда убирать debug-код.

---

### 5. **Журнал выполнения (Logger)**

**Проблема:** Функция возвращает значение, но «Выполнение» не показывает результат для простых строк.

**Решение:** Использовать `Logger.log()` для вывода информации.

**Правило:** Для отладки всегда использовать `Logger.log()`, а не рассчитывать на возвращаемое значение.

---

### 6. **Порядок загрузки данных**

**Проблема:** `launchesMap` была пустой, потому что `renderTree()` вызывался до завершения загрузки `loadLaunchesData()`.

**Решение:** Загружать данные **последовательно** или вызывать `renderTree()` **после** загрузки всех данных.

**Правило:** Асинхронные вызовы `google.script.run` — всегда использовать callback для продолжения.

---

### 7. **Работа с шаблонными строками**

**Проблема:** `\n` в комментариях внутри шаблонной строки ломает парсинг.

**Решение:** Не использовать `\n`, `\t` в комментариях и строках внутри template literal.

**Правило:** Внутри обратных кавычек `` ` `` избегать спецсимволов. Для переносов строк использовать конкатенацию.

---

### 8. **Проверка данных перед вызовом**

**Проблема:** Множество проверок «что возвращает функция» через alert.

**Решение:** Проверять данные **вручную** в редакторе Apps Script **сначала**, потом через веб.

**Правило:** Если вручную работает, а через веб нет — проблема в сериализации или развёртывании.

---

### 9. **Развёртывание**

**Проблема:** Изменения не применялись, потому что развёртывание не обновлялось.

**Решение:** Всегда после изменений: Ctrl+S → Развернуть → Управление развертываниями → ✏️ → Новая версия → Развернуть.

**Правило:** Без переразвёртывания изменения не попадут в веб-приложение.

---

### 10. **Типы данных в Google Sheets**

**Проблема:** `Number(row[4]) || 0` — если в ячейке строка, преобразование работает.

**Решение:** Всегда явно преобразовывать типы:
```javascript
id: String(row[0]),
qty: Number(row[4]) || 0,
status: String(row[6])
```

**Правило:** Не доверять типам из `getValues()`. Явно преобразовывать.

### 5. Специфика Google Apps Script
- Функции видны глобально между модулями
- После изменений: Ctrl+S → переразвернуть
- Ошибки часто связаны с кавычками и спецсимволами в HTML-шаблонах
- `google.script.run` — асинхронные вызовы к серверным функциям

### 6. Известные проблемы и их решения
- **Ошибка "Unexpected string"** → проблема с кавычками/экранированием → использовать `this` + data-атрибуты
- **Ошибка "Invalid or unexpected token"** → проблема с `\n` в комментариях или строках → убрать спецсимволы
- **Кнопки растягиваются** → добавить `flex: 0 0 auto`
- **Модалка перекрывает контент** → добавить `max-height` + `overflow-y: auto`
- **Нижняя панель перекрывает список** → добавить `padding-bottom` к контейнеру
- **Чекбоксы не выровнены** → `vertical-align: middle; margin: 0;`
